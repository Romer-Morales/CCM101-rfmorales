# Reflection – Laboratory Activity 6

1. What is the advantage of using Docker Compose instead of running multiple docker run commands?
Docker Compose allows me to define the entire application in one file and start everything with a single command. This reduces errors and makes the deployment much easier and more professional.

2. Why is it important to separate the web application and the database into different containers?
Separating them follows the multi-tier architecture principle. It makes the system more flexible, easier to scale, and easier to maintain. If one part has a problem, the other can still function.

3. What does “Infrastructure as Code” mean based on this laboratory?
Infrastructure as Code means defining the entire infrastructure (containers, ports, environment variables, etc.) in a configuration file instead of manually typing commands every time.

4. How did this laboratory change your understanding of real-world cloud applications?
I learned that real applications are rarely just one container. They are usually composed of multiple services that work together, such as a web application and a database.

5. How is your GitHub portfolio improving after six laboratory activities?
My portfolio now contains six complete laboratory activities. It shows a clear progression from basic Linux commands to Docker, object storage, and finally multi-container deployments using Docker Compose.
